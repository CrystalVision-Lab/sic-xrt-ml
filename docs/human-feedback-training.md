# 검수 자료의 일괄 학습

Data Tools Issue #33이 만든 `xrt_feedback_dataset_v1`을 읽는다. Analyzer Issue #54의 `xrt_feedback_v1` 원본 이력까지 패키지 해시로 확인한다.
학습·평가는 이 저장소가 소유하며 원본 수정·검수 UI·좌표 추출은 하지 않는다.

```powershell
python -m sic_xrt_ml.training.human_feedback --dataset "검수자료" --retained "기존개발자료" --validation-wafer 2 --inspect
python -m sic_xrt_ml.training.human_feedback --dataset "검수자료" --retained "기존개발자료" --validation-wafer 2 --output "새학습폴더" --epochs 15 --device cuda
```

현재 모델은 **후보 패치의 결함 유무 / BPD·TED·TSD 종류 / 중심 좌표 보정**을 별도 출력하는 연구용 CNN이다.
회귀는 좌표 보정에만 쓴다. 종류·유무는 분류다. 틀렸다는 클릭 자체를 reinforcement reward로 사용하는 방식은 아니다.
유무·종류·위치 마스크로 각각의 손실을 계산한다. 모르는 종류는 예측 라벨로 대체하지 않는다.
RGB128 입력에서 중심·문맥 특징을 사용하고 위치 출력은 축별 ±32px이다. 방향과 delta 보정 없이 회전·반전 augmentation을 하지 않는다.

기존 개발 cohort.json/samples.csv/sources.json/output_hashes.json 계약을 함께 읽는다.
학습 표본 추출은 기존 자료 50%, 검수 자료 50%를 기본으로 하고 각 유무/종류 그룹의 표본 질량을 균등하게 배분한다.
기존 자료의 라벨 근거는 기존 제공 주석 기반 연구 자료로 유지하며 사람 검수로 표시하지 않는다.
원본 해시가 동일한 프레임에서 새 확인 좌표 32px 근방의 기존 패치와 정확히 같은 패치는 해당 학습 실행에서 제외한다.
원본 자료 자체는 수정하지 않는다. JPG/TIFF 원본 해시가 다르면 반전/좌표 관계를 추측하여 연결하지 않는다.
그 대응은 별도 확인이 필요하다.

## 실행 전 조건과 평가

검증 웨이퍼는 사전에 지정한다. 같은 웨이퍼의 전후 영상·모든 점·패치는 같은 분리에 들어간다.
다른 웨이퍼에 같은 원본 해시/패치 해시가 있으면 거부한다. 최종 시험 웨이퍼 8은 언제나 금지한다.
학습 웨이퍼에서 실제 검수한 결함 10건·배경 10건, 검증 웨이퍼에서 각 5건, 기존 학습 자료가 있어야 기능 시험 학습을 시작한다.
이 수는 기능 시험의 최소 조건이며 충분한 품질·성능 확보를 뜻하지 않는다. 부족하면 needs_review_data 보고서만 만들고 학습하지 않는다.
종류 head는 각 종류 학습 자료 5건 이상, 위치 head는 위치 확인 학습 10건 이상에서만 학습한다.

고정 epoch 후 한 번 평가한다. 같은 검수 항목에 수정 중심/원래 중심 패치가 있어도 평가에서는 한 번만 센다.
원래 후보 패치가 있으면 그것을 평가하여 중심 보정이 쉽게 보이는 오류를 피한다.
유무는 결함 유지율·배경 제외율, 종류는 클래스별 support/혼동행렬/macro F1, 위치는 평균·중앙 픽셀 오차로 나눠 기록한다.
미검수·표시되지 않은 영역은 배경으로 평가하지 않는다. 전문가 정답을 보장하지 않으며 사람이 본 후보에 조건부인 성능이다.
누락 추가는 양성 자료로 사용되지만 전체 영상 검출기를 구현하거나 전체 영상 재현율을 증명하지 않는다.
기존 자료의 종류 일치도는 별도 기록하며 독립 정확도로 부르지 않는다.

report.json의 새/기존 예측 비교는 모델 출력이 남아 있는 같은 검수 항목만 비교한다.
위치는 보정 전 0 이동 오차와 비교한다. 기존 모델에 배경 종류가 없으므로 유무 baseline은 모든 후보를 결함으로 유지한 결과다.
원본 모델 해시가 다른 기록은 혼합 여부를 모델 해시 목록으로 보고한다.
기존 전체 자료에 대한 기존 배포 모델 비교와 전체 영상 누락 검증은 아직 없으므로 해당 비교 조건은 false다.
`deployment_ready=false`, `deployed=false`가 유지된다. 임계값은 학습 전에 .5로 고정하고 검증 결과를 보고 임의로 재선택하지 않는다.

결과는 plan.json/report.json/research_model.pt이다. checkpoint 계약 `review_multitask_v1_rgb128_raw_offset32`이며 학습된 head를 별도로 기록한다.
기존 3클래스 ONNX와 출력이 호환되지 않는다. 자동 ONNX 내보내기·서버 교체·검수 클릭마다 학습은 구현하지 않는다.
실제 적용은 기존 모델 비열화 비교, 전체 영상 누락 평가, 독립 검증, 새 inference 계약 연결을 마친 뒤 판단해야 한다.
